# Software Engineering Thoughts

Software engineering thoughts take the whole life cycle of software development as the starting point, and focus on standardization, normalization and engineering landing. Different from pure code design thinking, it pays more attention to team cooperation, project delivery, long-term operation and maintenance, and is the necessary advanced thinking for formal enterprise development.

## 1. Readability First
Excellent engineering code is not the most concise or the most clever, but the easiest to understand. Code is read far more times than it is written.

Practical performance:
- Clear naming and unified specification
- Moderate comments for complex business logic
- Reasonable blank lines and typesetting to optimize reading experience
- Avoid overly obscure writing skills and excessive clever code

## 2. Maintainability Oriented
In engineering projects, the cycle of later operation and maintenance is far longer than the development cycle. All design schemes need to consider later maintenance costs.

Core requirements:
- The structure is clear and the positioning of problem points is fast
- The function expansion is convenient and the reconstruction cost is low
- The historical problem records and modification ideas are complete

## 3. Refactoring Thinking
Code refactoring refers to optimizing the internal structure and logical arrangement of the code on the premise of not changing external functions.

Core scenarios of refactoring:
- The early rapid development code is chaotic
- Business iteration leads to bloated logic
- The old design can not adapt to new business requirements

Refactoring is not rewriting. It is gradual optimization and continuous improvement of code quality.

## 4. Testability Design
Engineering projects need to face long-term iteration and frequent regression testing. The code must be designed with testability in advance.

Common optimization methods:
- Decouple hard-coded data and external dependencies
- Extract independent small functions for unit testing
- Separate business logic and input and output processing

## 5. Standardization and Documentation
Standard specifications and complete documents are important symbols of mature engineering projects.

Including:
- Code writing specification and naming convention
- Interface document and business process description
- Environment configuration and deployment operation manual
- Version update record and modification instruction

## 6. Performance and Resource Awareness
Engineering thinking requires developers to have basic resource awareness, reasonably control memory occupation, connection consumption and response delay, and avoid resource waste caused by unreasonable code.

## Core Value Summary
Software engineering thinking makes software development change from scattered personal behavior to standardized team engineering behavior. It solves many practical problems in actual production, such as inconsistent styles, difficult cooperation, high maintenance costs and uncontrollable iteration risks.

For individual developers, establishing engineering thinking in advance can quickly adapt to enterprise development specifications, shorten the adaptation cycle of entering the team, and improve comprehensive engineering literacy.
