# What is REST?
REST stands for **Representational State Transfer**.
It is not a technology or framework — it is a **set of design rules** for building clean, scalable, and consistent APIs.

You can think of REST as a **common language** for backend services.
When APIs follow REST, developers can understand any system quickly.

## Key Principles (Simplified)
- **Client-Server Separation**: Frontend and backend are independent.
- **Stateless**: The server does not store user session data.
- **Uniform Interface**: Use standard HTTP methods and URLs.
- **Cacheable**: Responses can be cached for performance.
- **Layered System**: Use gateways, proxies, and load balancers.

## Why REST Matters (Enterprise View)
Nearly all large companies — including Google, Amazon, and cloud platforms — use REST APIs for:
- Microservices communication
- Mobile app backends
- Third-party integrations
- Public developer platforms

## Pro Tips from Industry
- You don’t need to follow REST *perfectly*.
- Follow it **consistently** so your team can maintain the project.
- REST makes scaling to millions of users much easier.
